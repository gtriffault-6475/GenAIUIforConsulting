- (version) Next.js 16.x (App Router, Turbopack) — vérifié web, actuel.
- (version) Drizzle ORM + better-sqlite3 — vérifié web, ORM par défaut des nouveaux projets Next.js en 2026, ~7.4kb gzip.
- (version) @anthropic-ai/sdk (Messages API + tool use) v0.124.0 — vérifié web, Node 20 LTS requis.
- (decision) Stack retenue : Next.js (monolithe, un seul process) + Drizzle/better-sqlite3 (SQLite fichier unique) + @anthropic-ai/sdk (Messages API directe, pas le Claude Agent SDK — jugé trop orienté 'agent codeur', embarque un binaire inutile ici). Contrainte motrice : round 1 doit tourner sur laptop, install très simple, pas de service externe à faire tourner.
- (decision) Paradigme : monolithe en couches (UI/application/domaine) avec frontière Ports & Adapters posée uniquement sur les intégrations Octopod/drive/Mattermost — adaptateur Mock pour round 1, adaptateur réel déféré. Choisi car c'est la frontière explicitement signalée mock-maintenant/réel-plus-tard par le PRD (FR-6, MVP §6.2).
- (decision) Périmètre opérationnel round 1 : mono-utilisateur, mono-poste (laptop du porteur de projet), démos en direct dessus. Aucun compte/auth, aucune synchronisation multi-poste, aucun déploiement serveur — le serveur Next.js local (localhost) suffit. Multi-utilisateur/auth explicitement différé, pas juste 'plus tard' mais hors de l'enveloppe opérationnelle de ce round.
- (decision) Génération des suggestions ancrées : produites par l'agent AU MOMENT de la création/modification d'un livrable (même appel qui produit le contenu, via un outil dédié côté tool-use), persistées immédiatement. Ouvrir l'éditeur ne fait que lire l'état persisté — aucun appel IA au chargement. Prévient : un futur build qui calculerait les suggestions à l'ouverture casserait le NFR d'immédiateté (PRD FR-24) et le climax d'UJ-1.
- (decision) Skill = définie dans le code (nom, instructions, outil associé éventuel) formant un catalogue global ; un projet référence une liste de skills chargées parmi ce catalogue (table de jointure). Le mécanisme d'ajout dynamique d'une skill (OQ-6 du PRD) reste différé — seule la forme minimale nécessaire à FR-11 est fixée ici.
- (decision) AD-1 Frontière Ports & Adapters sur intégrations OCTO (ProjectProvider/DriveProvider/MattermostProvider) — mock/real échangeables sans réécrire actions/domain.
- (decision) AD-2 Mutation exclusivement par Server Actions — seuls les fichiers actions/ importent db/ et integrations/.
- (decision) AD-3 Suggestions ancrées générées à l'écriture (création/modif livrable), jamais recalculées à la lecture — garantit l'immédiateté FR-24 et le climax UJ-1.
- (decision) AD-4 Skill = constante code dans skills/catalog.ts ; project_skill ne stocke que (projectId, skillKey).
- (decision) AD-5 Domaine pur (domain/) sans import db/integrations/actions/React — toute transition d'état (suggestion, stepper) y vit en fonction pure.
- (decision) Modèle de données (ERD) : Project, Conversation, Message, Document (source drive|manual, couvre FR-4), ProjectSkill, Livrable, Suggestion (type anchored|global, status pending|accepted|rejected|revising). Project.activeStepKey nullable pour le stepper avant-vente ; Conversation.proactiveSuggestionState pour FR-18 (non-réapparition).
- (decision) Arbre source : app/ (routes), components/, actions/ (un cluster par feature PRD §4), domain/, skills/, integrations/{ports,mock}, db/. Conventions : code en anglais / UI en français, ids via crypto.randomUUID(), enum suggestion status partagé, retour Server Action {ok,data|error}, secrets via .env.local (ANTHROPIC_API_KEY uniquement).
- (event) Spine distillée en ARCHITECTURE-SPINE.md (draft) — 5 AD, ERD, arbre source, stack, capability map, Deferred couvrant réel-Octopod, mécanisme skill, méthode qualification/data source références, workflow mission, révision globale, et l'enveloppe opérationnelle multi-poste/auth.
- (event) Réconciliation PRD + UX : 9 gaps trouvés (dont 1 contradiction : Deferred traitait 'révision globale crée-t-elle une suggestion ?' comme ouvert alors qu'EXPERIENCE.md le verrouille à non). Corrections : AD-6 (Conversation.stepKey, résout le lien stepper→conversation ET l'historique de suggestion proactive par étape), AD-7 (état suggestion proactive côté client, jamais persisté — résout la réapparition 'nouvelle session' sans notion de session), AD-8 (OverlayProvider unique — donne un mécanisme réel à la contrainte 'pas de pile de modale'), Document.folderPath (FR-3 répertoires), Livrable.conversationId (lien pour la révision globale), contrainte d'unicité suggestion pending en Consistency Conventions, actions/suggestion.ts ajouté à la capability map, note Deferred sur ownerId pour FR-9/FR-10 (confidentialité — sans objet en mono-utilisateur round 1, à construire si multi-poste).
- (version) Node.js 20 LTS remplacé par Node 24 LTS (20 est end-of-life depuis 2026-04-30, trouvé par le reviewer versions).
- (version) better-sqlite3 remplacé par node:sqlite (driver natif Node, zéro compilation native) — le reviewer versions a confirmé que la compilation native de better-sqlite3 est un vrai risque d'installation, contraire à la contrainte 'très simple à installer' de l'utilisateur.
- (version) TypeScript resserré à 5.7.x (au lieu de >=5.0) — TS 7 (rewrite Go) casse la compatibilité avec l'outillage Drizzle actuel, trouvé par le reviewer versions.
