## Intent

**Problem:** In the two-pane editor, a presentation imported from Drive is still read as plain text grouped under "Diapositive N". The consultant judges a suggestion without seeing the slide it lands on (layout, images, how much room the text has), and has to switch to Google Slides to check.

**Approach:** Owner request (2026-10-08), follow-up D1 of the two-pane editor spec. Each "Diapositive N" group of a Drive livrable shows an image of the real slide above its paragraphs, generated by the Slides API (`presentations.pages.getThumbnail`), loaded only when the group scrolls into view. Clicking the image opens the deck in Google Slides on that slide.

**Owner decisions (2026-10-08):**
- D1 — Images come from the Slides API thumbnails, not an embedded Google Slides frame. A frame needs the consultant's Google session inside an iframe, which browsers increasingly block (third-party cookies), and cannot be tied to one slide group. Thumbnails work with the app's own Google connection. Cost: one "expensive read" per slide image (Google quota: 60 per minute per user, 300 per minute per project), so images load lazily and are cached.
- D2 — The image shows the slide as saved in Drive, not the accepted changes not yet saved (Google renders only its own version). A slide with unsaved changes says so under its image: "Modifications non enregistrées : l'aperçu montre la version Drive." After "Enregistrer dans Drive" or "Réimporter", the images are refreshed.
- D3 — Images show by default while Google is `connected`; a toggle "Masquer les aperçus" / "Afficher les aperçus" in the document pane hides them, remembered per browser. Outside `connected` (disconnected, unconfigured) and in demo mode: no images, the text view of today.
- D4 — Only slides that already appear in the editor (those with at least one text zone) get an image. Slides with only images or tables stay absent, as today (Story 5.3).

## Boundaries & Constraints

**Always:**
- Image size MEDIUM (800px wide), PNG, shown at the document card's width with its aspect ratio reserved before it loads (16:9 placeholder, then the real `width`/`height`), so the text below never jumps.
- Lazy: an image is requested when its slide group comes within one screen of the document pane (`IntersectionObserver`, `rootMargin` one viewport), never all at page open. No request at page open for groups out of view.
- Server Action `getSlideThumbnail(livrableId, slideId)` → `ActionResult<{ url, width, height }>`: Drive livrable, `connected` only, `slideId` must belong to the livrable's blocks. Goes through the drive port (`getSlideThumbnail(fileId, slideId)`), the token-revocation wrapper and a 30 s timeout.
- Server cache (in memory, per process) keyed by `fileId:slideId`, entries kept 25 minutes (Google's URL lives 30). Cleared for the whole file after a successful save or reimport of that livrable, and the editor then re-requests the images in view.
- Loading: the reserved placeholder with "Chargement de l'aperçu…" (screen-reader text). Failure (quota, network, deleted slide): placeholder with "Aperçu indisponible" and a "Réessayer" button; the text below is unaffected. Errors are logged server side only.
- Image `alt`: "Diapositive N". The image is a link to `googleSlidesUrl(driveFileId)` + `#slide=id.{slideId}`, new tab, `rel="noopener noreferrer"`, with an sr-only "(ouvrir dans Google Slides, nouvel onglet)".
- Unsaved mark (D2): shown under the image when any block of that slide is modified (`isBlockModified`), `text-caption`, not colour only.
- Plain `<img>` with the Google URL (no `next/image`, no proxy through the app).

**Never:** No embedded Google iframe. No image for local livrables, in demo mode, or outside `connected`. No request for every slide at page open. No storage of image URLs in the DB, no migration. No rendering of unsaved text onto the image. No change to the two-pane layout, markers, links or suggestion actions.

## Code Map

- `integrations/ports/drive-provider.ts` -- `getSlideThumbnail(fileId, slideId): Promise<DriveResult<{ url: string; width: number; height: number }>>`.
- `integrations/google/drive-provider.ts` -- `slidesApi.presentations.pages.getThumbnail({ presentationId, pageObjectId, 'thumbnailProperties.mimeType': 'PNG', 'thumbnailProperties.thumbnailSize': 'MEDIUM' }, { timeout: REQUEST_TIMEOUT_MS })`; map errors like `readPresentation` (404 → `not_found`, 429 → `quota`).
- `integrations/mock/drive-provider.ts` -- `getSlideThumbnail` → `unknown` (never reached).
- `actions/google-drive.ts` -- the revocation wrapper covers the new method.
- `actions/livrable.ts` -- `getSlideThumbnail(livrableId, slideId)` action with the in-memory cache (module-level `Map`, server only); `saveLivrableToDrive` and `reimportDriveLivrable` clear that file's entries on success. `LivrableDetail` already carries `driveFileId`, `driveConnected`.
- `domain/livrable.ts` -- `googleSlidesSlideUrl(driveFileId, slideId)` beside `googleSlidesUrl`; `slideHasUnsavedChanges(blocks, slideId)` from `isBlockModified`.
- `components/SlidePreview.tsx` (new, client) -- observer, request, placeholder / image / failure + retry, link, unsaved mark; listens for a `slide-previews-refresh` event to drop its image and re-request.
- `components/SlidePreviewToggle.tsx` (new, client) -- toggle in the document card, `localStorage` in try/catch, sets a `data-previews="hidden"` attribute on the document pane that `SlidePreview` reads before requesting.
- `components/DriveLivrableActions.tsx` -- after a successful save or reimport, dispatch `slide-previews-refresh`.
- `app/livrables/[id]/page.tsx` -- in `LivrableBlocks` (bySlide), render `SlidePreview` at the top of each slide group when `driveConnected && driveFileId`; toggle above the groups.
- `app/globals.css` -- preview frame, placeholder ratio, failure state, toggle.
